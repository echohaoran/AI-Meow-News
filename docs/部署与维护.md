# 部署与维护

## 选择正确部署入口

新机器使用 `deploy/portable/compose.yaml`，本页通用命令均以它为例。既有homelab使用根 `docker-compose.yml`包含的 `deploy/ai-news/compose.app.yaml`；它只声明应用、复用外部`ainews-db`，不会创建数据库。不要在既有环境运行可移植模板。

既有环境所需仓库外文件为项目父目录 `.secrets/production.env`、`.secrets/backend-production.env`、`ops/production-release.env`及collector专用出站覆盖文件；env为受限配置，不能复制进仓库。`ops/collector-runtime-ed77.yaml`是该环境的实际覆盖文件，不是clone后自动存在的文件。既有部署命令必须同时保留原Compose项目名`source`、release env、两份-f路径、网络和data目录，避免另起一套服务。

## 独立 collector

先在后台核来源都是启用RSS且无detail抓取；当前独立入口拒绝其他来源，不能为了启动绕过校验。使用新模板时：

```bash
docker compose --env-file ../ai-news-runtime/compose.env -f deploy/portable/compose.yaml --profile collector up -d --no-deps collector
# 正常停用及恢复，不删队列或数据
docker compose --env-file ../ai-news-runtime/compose.env -f deploy/portable/compose.yaml --profile collector stop collector
docker compose --env-file ../ai-news-runtime/compose.env -f deploy/portable/compose.yaml --profile collector start collector
```

collector强制`COLLECT_ENABLED=true`、`MODEL_CALLS_ENABLED=false`，外推关闭。原生`cron.sources.schedule`每分钟Asia/Shanghai安排到期源，`sources.fetch`并发2，单条来源仍按自己的抓取间隔。没有新建宿主cron或平台自动化，也不重复启动第二个采集实例。

仅采集会排后续content任务；队列created增长不等于失败，也不代表已分析。停止宽限515秒用于排空在途工作；正常停用使用stop，让进程完成退出，避免kill。stop保留来源排程、内容、回执与队列；不等于删除所有定时记录。

既有homelab停启使用下面命令（仅既有运维身份）：

```bash
docker compose -p source --env-file ../ops/production-release.env -f docker-compose.yml -f ../ops/collector-runtime-ed77.yaml --profile collector stop collector
docker compose -p source --env-file ../ops/production-release.env -f docker-compose.yml -f ../ops/collector-runtime-ed77.yaml --profile collector start collector
```

## 完整 worker 与预算

完整worker是单独`worker` profile，默认不启动。它注册正文、分析、归组、综述、内容sweep、热点、报告、通知及模块任务，启动可能立即领取旧积压；模型阀关闭也不等于队列完全不被处理。

需要完整处理时先检查旧created/active/unfinished回执、选稿规则、每个能力的模型路由、服务密钥、请求预算及其他付费服务。不要同时让两个角色争用同一采集队列。先正常停collector，再准备受审的worker专用Compose覆盖，精确设其`COLLECT_ENABLED`和`MODEL_CALLS_ENABLED`，外推保持独立关闭；模板中的environment优先于env_file，只改env文件不会覆盖模板硬性false。

审查完成后才以同一Compose上下文运行 `--profile worker up -d --no-deps worker`。停用对应 `--profile worker stop worker`；后续恢复collector仍用原上下文。这里是人工维护步骤，不是本仓本次发布会自动执行的动作。当前完整worker仍关，未改变预算，也未释放旧积压。

## 升级

1. 记录当前镜像ID、release、配置文件身份、数据目录和数据库身份；配置备份在仓库外，权限0600。拉取前确保本地用户改动已保存，不reset/clean或force。
2. 做数据库及附件配套备份，并在隔离空库验证恢复。新版本SQL先审查迁移；从0055起遵守在线单语句约定，不修改已发布迁移账本或用回滚SQL猜测恢复。
3. 构建新的不可变tag，检查Compose解析、web秘密隔离及监听端口。重型构建/测试与部署串行；homelab使用既有项目锁。
4. 正常停止会写业务的worker/collector，按原上下文跑一次tools/migrate。不要把seed/历史导入作为每次升级必跑步骤。
5. 仅更新需要变更的服务，按原profile恢复collector；API/web可继续使用独立已验镜像，不必跟随纯文档提交重建。
6. 验收health release、来源ID/标题/原日期/原文、详情、筛选、真实精选及空日报边界；核模型回执/预算/任务状态。HTTP200只是连通性证据，不是内容链路全部通过。

## 备份与恢复

备份至少包含PostgreSQL自定义格式dump、数据目录中uploads与本地feedback-screenshots、对应版本配置及镜像引用。模型回执、审计、队列、迁移账本都在数据库中；不要为回退页面覆盖已新增的业务数据。对象存储备份是完整worker的任务，当前collector不运行它。

新模板手动导出数据库示例（在仓库根，备份路径自行准备）：

```bash
umask 077
mkdir -p ../ai-news-backups
docker compose --env-file ../ai-news-runtime/compose.env -f deploy/portable/compose.yaml exec -T db pg_dump -p 43183 -U ainews -d ainews -Fc > ../ai-news-backups/ainews.dump
# 另在无附件写入的检查点备份data中的附件；记录时间和文件SHA。
```

恢复验证只能指向隔离空库，使用兼容版本pg_restore，并检查表、计数、附件引用及权限。正式恢复先停止本项目写入者、核对目标库并另存失败现场；同时恢复匹配的附件和配置。只恢复dump不能找回本地附件，只有pg_dump退出0不能称恢复已验证。当前文档维护没有执行生产备份/恢复或新增迁移。

## 回退与排障

应用回退使用已记录旧镜像与对应配置，只切该项目服务，保留现有DB和回执。若涉及不兼容迁移，先设计数据恢复，不手工删schema_migrations或直接覆盖旧dump。停collector是最小采集停用，不是数据库回滚。禁止用`down -v`清理故障。

| 现象 | 核查顺序 |
|---|---|
| 43180不可达 | 入口绑定/防火墙、ingress→web、web→API、API health |
| 来源页为空 | 来源启用、可信发布时间、collector心跳、fetch_runs、出站网络；seed不是采集 |
| RSS偶发失败 | 真实HTTP状态、代理、订阅返回格式、下次原生周期；不要反复force |
| 新增为0 | 对比原生去重/游标和源是否有新条目，不把重复found当新增 |
| 资料增长但精选不变 | 完整worker是否关闭、队列状态、双评分及发布资格 |
| 热点/日报为空 | 近期独立参与者和报道方、版次窗口、历史回填/评分；不改时间凑内容 |
| 后台无法登录 | ADMIN_PASSWORD或飞书配置、production秘密校验、Cookie/Origin/CSRF |
| 模型被熔断或unfinished | 回执与预算及请求结果，不换label或删回执盲重试 |
| data写入失败 | UID1000和精确目录权限，不放宽整个项目 |

日志只取必要范围并脱敏；不导出完整env、模型原始请求响应、token、私钥或用户会话。公开说明与运行证据分开保存，历史数量只在带日期的状态摘要出现。
