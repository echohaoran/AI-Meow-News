# AI-News 后端运行与部署交接

权威源码：homelab /mnt/local_data/Repo/AI-News/source，所有命令在 ainews@192.168.1.77 的 bash -lc 内执行。基础设施只使用项目根 ops/compose.dependencies.yaml；不要运行上游根 docker-compose.yml 创建重复库。

## 本机开发入口

先进入 source 并 source ../.tooling/development-environment.env。Node 24.22.1 直接执行 TypeScript，无后端编译产物。

- 迁移：node deploy/ai-news/run.mjs development migrate
- 首次种子：node deploy/ai-news/run.mjs development seed；按ID不覆盖已有信源。
- API：node deploy/ai-news/run.mjs development api；默认127.0.0.1:43182，API_BASE_URL=http://127.0.0.1:43182 供web服务端读取。
- 有界采集：COLLECT_ENABLED=true MODEL_CALLS_ENABLED=false node deploy/ai-news/run.mjs development collect-once rss-openai-news 3
- 模型连接验收：MODEL_CALLS_ENABLED=true COLLECT_ENABLED=false node deploy/ai-news/run.mjs development model-check
- worker：node deploy/ai-news/run.mjs development worker；常驻采集/模型需显式设置对应安全阀 true。通常保持关闭；单次 RSS 验收无需启动 worker。
- 后端本地行为测试：bash deploy/ai-news/check-backend.sh（非阻塞 flock，锁被占用退出75）。
- 真实API验收：node --env-file=../.secrets/development.env deploy/ai-news/api-check.ts；只读取实际开发库及43182。
- 生命周期验收：node deploy/ai-news/process-check.mjs；只控制本任务证据目录记录的API PID，重启API、检查持久化，再启动/停止worker。它会影响临时API，不在集成进行中执行。

run.mjs 安全读取根 .secrets/<profile>.env 和可选 .secrets/backend-<profile>.env。保留既有 OPENAI_* 并映射为框架 LLM_BASE_URL/LLM_API_KEY/LLM_MODEL，不打印值。AI_ENABLED 不自动打开模型。运行目录是项目 .runtime/<profile>/data，缓存/.tmp 也在项目根。生成的报表、DB、依赖和密钥均不进源码。

现有 development.env 只有数据库及模型配置，无管理员登录/会话/图片签名配置。当前开发API以匿名只读运行，后台保持401；若要开发后台登录，由运维安全生成 backend-development.env，字段见 deploy/ai-news/backend.env.example。禁止使用 DEV_AUTH_* 代替真实登录验收。测试库已通过随机临时密码的真实会话、CSRF和注销测试。

## 生产模板与运维步骤

deploy/ai-news/compose.app.yaml 只定义 api/worker/migrate，加入现有 external ainews-db，生产DB仍为 ainews-postgres:43183，不发布数据库或API到LAN。新增应用网络名 ainews-app，API服务名 api（同网络http://api:43182）；web和入口服务由全栈最后合并，web43181内部，唯一LAN入口43180。

1. 全栈审查前后端diff，统一根Dockerfile/构建注册和说明文档，构建一个带版本标识的应用镜像。模板不重复安装基础设施或自动部署。
2. 运维在根 .secrets/backend-production.env 安全设置 SESSION_SECRET、IMG_PROXY_SIGN_SECRET、至少12字符ADMIN_PASSWORD；若用推送另设独立INGEST_TOKEN。文件0600，生产不能存在DEV_AUTH_*；值不进Git/日志/前端。
3. 运维准备 AI_NEWS_DATA_DIR 对容器node用户可写，设 AI_NEWS_IMAGE 为已审查镜像。不得把完整 docker compose config 输出到日志，可能展开敏感env；语法检查只用 --quiet。
4. 在现有项目数据库做备份，再用 docker compose -f deploy/ai-news/compose.app.yaml --profile tools run --rm migrate；成功后启动api。迁移权限限当前项目普通角色，不借业务/管理凭据扩权。
5. 全栈合并web及入口，API_BASE_URL=http://api:43182，web只得读HTTP，禁止传入backend env_file。检查唯一43180入口、真实来源动态、详情、认证、撤回和缓存。
6. worker默认profile关闭，采集/模型默认false。审核已启用信源及每服务预算后，才启动worker并按实际需求显式打开安全阀；站内读取永不打开这些阀。外推/IndexNow本模板持续关闭。

容器模型服务地址为已有LAN服务 http://192.168.1.77:10100/v1，默认模型gpt-6-luna。真实连接验收已通过框架回执和预算；此次未验证整条新闻预筛/评分/写作/归组流程。该中转JSON模式会要求用户输入含json字样，验收脚本已加小写json；编辑流程的所有结构化提示词兼容性尚须在受控模型接入验收中核对，不能从连接成功推断整条流程成功。

## 数据与回滚

本轮没有新增/修改SQL迁移；将上游64项已有迁移分别应用在ainews_dev和ainews_dev_test，生产库未迁移。新来源投影使用既有publications表，原文摘要在articles.excerpt，生成结果仍在analyses，人工覆盖仍在editorial_overrides。新投影不是精选，不写分析结果或核验通过。

回滚应用时由全栈切回已审查版本并关闭worker/安全阀；无需执行新增DDL回滚，保留真实采集数据和回执。来源动态入口会消失，已有未精选投影不会伪装成精选。只有确认需要恢复迁移前数据库时才由运维从已验证备份恢复，禁止手工删除schema_migrations或倒改历史迁移。

测试不需要CREATEDB：新测试及选定既有测试在预建*_test库顺序执行。完整npm test的分库副本仍需要额外测试运行身份，本轮未执行，也未对普通角色扩权。

当前临时API供全栈联调，非服务托管或整站上线。进程ID及安全开关见证据目录process-check.json；API退出后按上面的开发入口启动。worker已退出。没有重启数据库容器，本轮持久化证据仅覆盖API重启和新数据库连接。
