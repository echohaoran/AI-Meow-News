# OpenRouter 排行榜

`/rankings` 展示每天保存的 OpenRouter 排行榜快照。电脑侧栏增加“排行榜”，手机从“我的 → 工具与入口 → 排行榜”进入；该页归属“我的”，返回仍回到“我的”，不增加底栏标签。

## 范围与口径

- 9 类模型榜：文本、图片、视频、语音合成、决策、向量嵌入、重排、语音转写、批处理。
- 模型榜提供近 1 天、近 7 天、近 30 天与增长趋势；应用榜提供前三个周期。
- 页面及各用量榜标题明确写为“使用排行榜”；能力基准保留独立的能力标题，不将 token 或请求量称作性能。
- 所有模型榜与能力基准的模型名前展示发布厂商 Logo，免费与批处理变体沿用同一厂商图标。复用现有 `BrandMark` 展示，当前快照的 62 个发布者均映射到随构建发布的静态 Logo，不依赖读者网络加载外部图片、不引入依赖；图标来源及许可见 `modules/openrouter-rankings/web/marks/NOTICE.md`，未知的新厂商先显示名称缩写。应用榜不套用模型厂商 Logo。
- 能力基准分别展示来源页面提供的 Artificial Analysis 与 Design Arena 分榜，保留分数/ELO 的不同单位。每份榜单最多展示 50 个条目。
- 文本按输入加输出 token 排序，图片按实际返回图片的请求数，其余类别按来源请求数/子请求数。增长趋势按环比增长率，缺少前期比较数据的模型标为“新”。不把平台用量解释成模型能力或全行业份额。
- 标准模型、free 与 batch 变体分别处理；模型目录中的 endpoint.variant 决定名称归属，不能用同一 permaslug 的最后一项覆盖标准模型。
- 数据截止日期来自来源记录中的最新 UTC 日期，采集时间单独显示为北京时间。能力基准与应用接口未提供独立截止日期时明确说明，不自行填写。
- 原站的历史趋势图、任务/语言分布图、会话成本图没有复制为本站图表；本页提供的是模型、能力基准和应用排名。

## 运行

模块位于 `modules/openrouter-rankings/`，通过 `site/modules/` 三份清单接入。没有更改共享导航实现或文章详情，也没有新增外部依赖；锁文件仅增加本地 workspace 的元数据。

完整 worker 在北京时间每天 **08:15** 执行 `cron.openrouter.rankings`；错过的运行由现有 pg-boss `missed: once` 机制补一次。只有 `COLLECT_ENABLED=true` 才注册并执行。单独的 RSS collector 不运行这个任务。

采集读取 OpenRouter 网页使用的公开 JSON 接口，每轮 39 次读取、最多两个并发，不需要新增 API 密钥，也不调用模型。不同抓取结果均在本轮结束后处理。worker 停止时不再开始下一批请求。

数据存入现有 `settings` 的 `public-snapshot:openrouter-rankings`，无需数据库迁移。公开接口 `/api/site/rankings` 仅通过 `packages/backend/src/publication/snapshots.ts` 读取该公开命名空间，支持 ETag/304 与 5 分钟缓存。页面访问和切换榜单不会触发外部采集；页面内各查询条件共享同一份快照缓存。

单个榜单失败时保留其上一次成功快照和原采集时间，并在页面说明未更新；首次尚未成功时显示空态。模型目录整体失败则任务失败，原快照不变。任务结果在现有后台运行记录中可查。

部署新镜像后，需要在使用既有后端环境的 worker 任务中完成一次首次采集：

```bash
COLLECT_ENABLED=true node modules/openrouter-rankings/scripts/refresh.ts
```

随后由日程自动更新。沿用项目现有环境加载和 Compose 上下文，不把生产 env 复制进仓库，不另启动第二个长期 worker。早期侧对话只完成本地开发和隔离验证；后续已由主会话统一部署，首次真实采集得到 71 份榜单，当前版本和验收范围见[交接记录](handoff.md)。

公开页面保留 OpenRouter 来源链接、统计时间及 CC BY 4.0 署名；列名和展示格式由本站整理。公开网页接口未来调整时需要重新核对，不能将错误响应当作空榜发布。
