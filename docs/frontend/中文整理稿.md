# 中文整理稿

2026-10-27，用户要求中文和英文原文都整理成中文后阅读，修复文章页“正文暂不可用”的问题。

## 原因与最终行为

爱范儿示例 `k3edcxu3hit5wl3v3p7s2qojo` 实际已采集 3,816 字正文，`body_status=ok`；新来源默认 `site_fulltext=false`，发布层因此为 `body_mode=summary`，原有详情页没有返回原文正文，却把这个状态笼统显示为正文不可用。

本站 `modules/chinese-reading` 在后台将可用中英文素材提炼、独立组织成中文整理稿。它围绕事实写作，保留数字、主体、时间、条件与来源声称，删除推广、返佣、订阅招揽和作者联系方式，不逐句复制或翻译整篇报道，不补写素材没有的信息。页面标注“中文整理稿 · AI 辅助”，原文按钮、来源/作者、推荐信息及两侧栏继续保留；目录按实际生成的小节标题生成。

原始全文许可保持原样，中文整理稿不被当成原文或全文翻译，不进入仅限允许转载原文的全文 RSS。来源要求仅展示摘要（publication visibility 为 `summary-only`）和撤回条目不生成或展示整理稿。确实没有取得正文时仍显示真实状态和原文入口，不伪造缺失材料。

## 实现边界

- 站点模块注册 `itemReading` 只读扩展，详情与 Markdown 都由 `packages/backend/src/publication/` 统一读取；请求页面不会采集、排队或调用模型。
- `reading.compose` 在原 worker 中每 5 分钟处理公开文章，优先精选和较新内容。仅在 `MODEL_CALLS_ENABLED=true` 时调度；使用既有 translate 模型路由、`translate_body` 回执与预算，不增加模型服务或提高预算。
- 数据复用 `translations`，独立键 `lang='zh-reading'`，保留既有 `zh` 译文和来源原文。不新增库表/列或修改历史迁移。读取、写入都匹配当前文章 revision，模型返回期间原文变化时不写入旧整理稿，已付费回执仍正常完成。
- 模型返回结构化中文标题和段落，生成安全 HTML 后沿用目录逻辑。模块未完成时返回 pending；已有可读正文可继续阅读，详情每 10 秒刷新，整理完成后替换。尚无可读正文时明确显示后台正在生成。
- 安装本站中文整理模块后，原生正文翻译定时任务只继续处理 X 帖及引用，避免同一篇文章重复做完整翻译和独立整理；不安装模块的站点继续原来翻译流程。模型管理中的步骤名同步为“中文阅读与翻译”。
- `deploy/ai-news/compose-readings.ts` 接收显式文章 ID，复用相同生成函数、回执和预算来补写；遇到服务关闭、预算耗尽或服务故障停止，不释放未知回执、不重置已有内容。

## 验证

Homelab 独立 `_test` 数据库与本地假模型验证 4 项集成行为：中英文来源在摘要许可下均能显示独立中文稿、页面读取不调用模型、完成后不重复计费、旧 revision 的延迟答案不会覆盖新稿、撤回后不可读取或导出。另有 39 项发布/翻译回归、7 项页面 SSR 回归、类型检查及前端构建通过。测试不连接外部模型或采集服务。

实际模型生成、浏览器目录及部署与备份记录见 `docs/handoff.md` 本次条目。此次旧文回填按真实进度记录，不把等待或失败项算作已完成。
